## 0. 校正后的全局流程（先给总图）

```
输入：实验背景文本 + 标注肽段集合(label/置信度/谱图/对应蛋白/Meta) + 蛋白集合(Meta)
   │   （上游"谱图→肽→蛋白鉴定"对我无感知，已给定）
   ▼
任务一：构建若干【通用知识图谱】(蛋白-疾病 / 蛋白-免疫 / 蛋白-物种 …)，源自公共数据库
   │   对鉴定出的蛋白做【证据分级注释】：
   │     · 库里有直接关联 → 结论(直接证据)
   │     · 库里没有、靠 KNN 外推 → 假说(逻辑推导)
   ▼
任务二：构建【本次实验知识图谱】= 输入 + 上面补的 Meta，展示实验结果的关联关系
   ▼
deep-search：找辅助/直接证据 → 认知态跃迁
   · 假说 + 直接证据 → 结论
   · 假说 + 无证据   → 仍是假说
   · 假说 + 反证     → 伪理(被证伪的假说)
   ▼
报告
存储：MySQL(关系/数据平面) + 图数据库(知识图谱)
```

## 2.〔校正 B〕我的真实输入（三件套）

**师兄原意：**
1. **实验背景**（例：Jak2/Stat3 通路在急性脑缺血再灌注损伤 CIRI 中的作用；AAV9 基因沉默 + tMCAO 大鼠模型；DIA 蛋白质组比较 tMCAO+shNC vs tMCAO+shJak2）。
2. **肽段集合**：一组或多组（多组=实验组/对照组，**带 label**）；每条肽→1 个蛋白、→1 或多张谱图；带**置信度**；可能带 Meta（亲和力、保留时间…）。
3. **蛋白集合**：→若干肽段；带 Meta。

**我的分析：**
- 这是一份**定量 / 差异**蛋白质组（DIA，case vs control），不是单样本。**"定量/差异"在旧 spec 里被降级为可选——现在它是核心**（整个实验目的就是比较两组）。
- **实验背景文本是"指挥棒"**：它点明了疾病(脑缺血)、通路(Jak2/Stat3)、物种(大鼠)、设计(敲低 vs 对照)——决定了**哪些通用知识图谱/关联才相关**（该去问"蛋白和脑缺血/免疫有没有关系"，而不是泛泛注释）。
- 多组 + label ⇒ **差异分析**（哪些蛋白在 shJak2 组显著变化）是"从统计学角度"解释的起点。

**改进方向：**
- 定义**输入 schema**（肽表 / 蛋白表 / 组别 label / Meta / 背景文本），落 MySQL。
- 背景文本要**结构化抽取**（疾病、通路、物种、分组），作为后续知识查询和报告的锚。
- 把**差异分析**纳入：组间比较 → 差异蛋白集合 → 喂给任务一做富集/关联。
- **解释范围采用分层处理**：全部已鉴定蛋白接受 UniProt/CTD 基础注释并作为实验背景保留；差异蛋白才进入富集、Foldseek 结构 KNN、假说生成、deep-search 和报告重点解释。这样既不丢失全量背景，也控制图规模和推理成本。

## 3.〔任务一〕通用知识图谱 + 证据分级注释（本项目重心）

**师兄原意：** 准备几个 general 数据库（蛋白-疾病、蛋白-免疫、蛋白-物种…），构建几个不同的知识图谱；从统计学角度给鉴定蛋白附加 Meta。库里**直接有关联→结论**；**没有→用 KNN→假说**。

**我的分析：**

**3.1 这推翻了"知识不入图"。** 早期定的"疾病/免疫不建节点、只在线查"作废；现在要**实打实建多个通用知识图谱**当知识底座。（也就是最初你师兄问"建几个知识图谱"的真正意图。）

**3.2 数据库已定（师兄 2026-06 确认，三个基本够用）：**

| 库 | 角色 | 形式 | 证据语义 |
|---|---|---|---|
| **UniProt** | 蛋白属性：结构域 / 组织表达 / 物种 | **师兄已封装成 MCP 工具**，我在其上扩展建 KG | 直接注释 = 结论级事实 |
| **CTD** | 蛋白-疾病 关联 | 蛋白-疾病 KG（可下载） | 直接命中 = **结论** |
| **AlphaFold DB** | 结构 → **找 K 近邻** | 结构相似检索（实践用 Foldseek 在 AF 全库搜） | 结构近邻借关联 = **假说**；顺带跨物种桥 |

不再单列 DisGeNET/ImmPort/OrthoDB——疾病走 CTD、属性/物种走 UniProt、相似走 AlphaFold 结构。免疫维度当前不单建库，先从 UniProt GO、CTD 与 deep-search 获取；但能力不关闭，预留免疫节点/关系、`ImmuneKnowledgeProvider` 适配器和导入通道，后续可按实际需求启用专用数据源。
**CTD 注意**：它是 gene 为中心、且含"通过化学物推断"的间接关联——做"结论"时应**只取 curated/marker 直接证据**，推断类降为较弱证据。

**3.3 关键洞察——跨物种桥由"结构 KNN"天然解决。** 实验是**大鼠**，而 CTD 疾病知识多以**人**为中心。妙处：**AlphaFold 结构 KNN 是物种无关的**——一个大鼠蛋白的结构近邻里自然包含人源蛋白，后者带 CTD 疾病关联。于是"结构找近邻"一步**同时完成** ①假说外推 和 ②大鼠→人桥接，不必再单建同源映射库。

**3.4 三态认知模型（结论 / 假说 / 伪理）——给它正式定义：**

| 态 | 含义 | 来源 |
|---|---|---|
| **结论** | 有确切证据 | 通用 KG 里**直接命中**的关联（含统计富集显著 + 直接收录） |
| **假说** | 有逻辑推导、待验证 | **KNN/网络邻近/富集外推**得到（蛋白本身没收录，但它的近邻被收录） |
| **伪理** | 被证伪的假说 | deep-search 找到**反证**的假说（负结果也要留档，别丢） |

每个附加到蛋白上的 Meta 属性都带：`value + evidence_level(结论/假说/伪理) + source + 推导依据(假说:哪些近邻)`。

**3.5 "从统计学角度"——我的理解（需师兄确认）：** 不是逐个蛋白贴标签，而是对**差异蛋白集合**做**富集/过表达分析**（这组蛋白是否显著富集于"脑缺血相关""免疫相关"基因集），显著且直接收录→结论；靠 KNN 把未收录蛋白拉进来→假说。

**改进方向：**
- 选库 → 各建一个通用 KG（落图数据库），节点统一到可互映的 key（protein/gene + 物种）。
- 实现"证据分级注释器"：direct-hit→结论；KNN 外推→假说；输出带 evidence_level 的 Meta。
- **复用 `pkg/hypothesis`**：把"取共识"从 GO/EC 改成"疾病/免疫关联"的外推。
- **KNN 空间已定 = 结构相似（AlphaFold DB）。** 比序列/网络更稳：结构比序列保守，结构近邻共享某关联的逻辑更强；实践用 **Foldseek** 在 AF 全库做结构检索，取 top-k 结构近邻 → 查其 CTD 疾病关联 → 假说。

## 4.〔任务二〕本次实验单独的知识图谱

**师兄原意：** 基于输入 + 我补的 Meta，构建本次实验的知识图谱，展示实验结果的关联关系。

**我的分析：**
- 这是**交付级的实验图谱**：把本次鉴定的蛋白/肽（带组别、差异、置信度）和它们从任务一得到的疾病/免疫/物种关联（带结论/假说标签）**整合成一张关联图**。
- 它是**实例化**的（针对这次实验/这批蛋白），而通用 KG 是**可复用**的知识底座——两层要分清：通用 KG 是"字典"，本次 KG 是"这次的故事"。
- Jak2 例子里，这张图要能讲出："敲低 shJak2 后差异蛋白 X/Y/Z；X(结论)与脑缺血直接相关、Y(假说)经 KNN 提示免疫相关、Z…"。

**改进方向：**
- 定义本次 KG schema：节点 `Protein/Peptide/Group` + 引用到 `Disease/ImmuneTerm/…`；边含**关联**(带 evidence_level)与**差异关系**(组间上下调)。
- 通用 KG 与本次 KG 采用混合衔接：公共实体/稳定事实引用通用 KG，本次实验判断保存在实验工作区并在完成后冻结归档。

## 5.〔后续〕deep-search 的角色 = 认知态跃迁

**师兄原意：** 后续就是 PDF 里的 deep-search；找辅助/直接证据，有直接证据升级为结论，没有就是假说，被证伪就是伪理。

**我的分析：**
- deep-search 不变其"在线找证据"的本质，但**作用对象变了**：它去验证任务一产出的**假说**，并**更新本次 KG 里 Meta 的 evidence_level**。
- 这是一个**状态机**：`假说 --(直接证据)--> 结论` / `假说 --(无证据)--> 假说` / `假说 --(反证)--> 伪理`。
- 伪理要留档——deep-search 里证伪是常态，负结果对科学解释同样有价值。

**改进方向：**
- deep-search 输出统一成"对某条假说的裁决(支持/无/反对) + 证据引用"，回写 evidence_level。

## 6.〔存储〕MySQL + 图数据库 + 实验数据库归档

**师兄原意：** 库本身提供了 MySQL，也可额外引入知识图谱数据库。

**我的分析 / 改进方向：**
- **MySQL = 关系/数据平面**：输入三件套（肽/蛋白/Meta/label/背景）、公共库下载的缓存、Meta + evidence_level、deep-search 证据。对应现有"数据平面"思路，从 SQLite 升到 MySQL。
- **Neo4j = 知识图谱层**：承载通用 KG 与本次实验 KG 的关系遍历，通过 `GraphStore` 接口访问，避免业务代码直接绑定驱动。
- 分工原则：**MySQL 是事实唯一来源**；Neo4j 只保存关联、必要索引字段和 `mysql_ref`，重数据、证据正文和状态历史留在 MySQL。
- **本次实验 KG = 实验工作区中的可变状态**：deep-search 期间允许 `HYPOTHESIS → CONCLUSION/REFUTED`；公共实体和稳定事实引用通用 KG，本次实验的差异、假说、证据等级和裁决绑定 `experiment_id` 单独保存。
- **实验数据库 = 冻结归档层**：验证完成后，把本次实验 KG 连同证据状态历史、公共库版本、分析参数和报告引用冻结为只读快照；统一按 `experiment_id + snapshot_version` 管理，不为每次实验新建一个数据库。
- 快照不得覆盖：发现新证据或使用新版通用 KG 重分析时创建新版本。实验结论仍受具体实验条件约束，不自动写回通用 KG；提升为公共知识需独立审核。

生命周期：

```
通用 KG（公共事实）
        ↓ 引用
本次实验 KG（工作区，可变）
        ↓ deep-search 完成 + 冻结
实验数据库（只读、版本化快照）
        ↓
报告 / 审计复现 / 跨实验比较
```

> ⚠️ 本节是**原始分析清单**。**执行版**（按依赖排序 + 上游划掉 + 最小闭环 + 阻塞标注）以 [`PROJECT-STATUS.md` §8](PROJECT-STATUS.md) 为准，二者若冲突听 §8。

2. **定输入 schema** 并落 MySQL（肽/蛋白/Meta/label/背景）。
3. **选库 + 建通用 KG 骨架**（先 protein-disease，做最小闭环）。
4. **证据分级注释器**：direct→结论 / KNN→假说（复用 `pkg/hypothesis`）。
5. **差异分析 + 富集**：组间比较 → 差异蛋白 → 富集/外推。
6. **本次实验 KG 构建**：整合输入 + Meta，输出实验工作区中的可变关联图。
7. **deep-search 接认知态跃迁**：假说→结论/伪理回写，并保留状态历史。
8. **实验数据库归档**：验证完成后冻结只读快照，绑定版本、来源、参数和报告。
9. **报告**：从冻结快照按结论/假说/伪理分层呈现。
