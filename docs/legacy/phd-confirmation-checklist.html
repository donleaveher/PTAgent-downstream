关系图谱 · 与 PhD 要敲定的细节

逐条过，把结论填进每项的「PhD 结论」。优先级： 先锁 决定整体走向 · 需确认 loader/数据级 · 确认默认 已有默认、确认即可。

为什么要先锁 A 组：A 组(范式级)决定蛋白层挂不挂、输入是什么格式——B/C/D 全部建立在它之上。A 没定，下面别动手。当前仓库唯一落地的解析器是 Casanovo(de novo)，默认就走 de novo 主干(到 Peptide 即止)。

速览：最关键的几条

#问题不定会怎样
A1走 de novo 还是数据库搜索决定蛋白层(Protein/Group/GDS 推断)整层挂不挂
A4上游分析工具是哪个决定输入文件格式 → loader 怎么写
B1Casanovo 实际吐 mzTab 还是 JSON仓库内已钉 mzTab，但部署工具未证；错了 loader 全废
D2报告受众 QC / 生物学解读决定要不要做「解释与注释 Agent」这层
E1Neo4j 是否装 GDS 插件不装则蛋白推断(连通分量)跑不了

A. 范式级（最先锁）

A1 走 de novo 还是数据库搜索？ 先锁

影响：de novo(Casanovo) 只到 Peptide、无蛋白归属；数据库搜索(MaxQuant 等)才有 Protein/ProteinGroup 层与 GDS 连通分量推断。这条直接决定整个蛋白层要不要建。

我们的现状：仓库唯一解析器是 Casanovo(de novo)，默认走主干 Sample→Spectrum→PSM→Peptide，蛋白层代码写好了但不挂。

PhD 结论：
A2 实验范式：DDA / DIA？ 先锁

影响：DDA 窄窗一谱≈一肽；DIA 宽窗一谱混多肽 —— 决定 Spectrum→Peptide 主干边的基数(1:1 还是 1:n)。

我们的现状：当前 join 按「一谱一预测」(Casanovo/DDA 式)实现。

PhD 结论：
A3 定量策略：LFQ / TMT / SILAC / 不做定量？ 先锁

影响：决定要不要 Quantification 节点、怎么挂(无标/同重标签/同位素)。de novo 通常无定量。

我们的现状：schema 暂无定量层，Casanovo 结果也无强度。

PhD 结论：
A4 上游分析工具具体是哪个？ 先锁

影响：Casanovo / MaxQuant / FragPipe / DIA-NN —— 直接决定输入文件格式，loader 按格式写。每换一个工具就要新写一个 loader。

我们的现状：只有 Casanovo loader(吃 mzTab)。

PhD 结论：

B. Casanovo / 数据格式（loader 直接依赖）

B1 Casanovo 部署工具实际吐标准 .mztab 还是被包成 JSON？ 需确认

影响：loader 完全按格式写；猜错则整条入图链路报错或静默失效。

我们的现状：仓库内已钉死 mzTab(解析器 + 测试 + 锚定 Casanovo ms_io.MztabWriter)；但部署的外部 MCP 工具是最终权威，代码证不了。请确认它跑出来的是不是标准 .mztab。

PhD 结论：
B2 Casanovo 工具注册后的真实 tool_name 是什么？ 需确认

影响：materializer 按 tool_name 选 loader。注册表 key 必须等于真实工具名(可能带 mcp. 前缀或 _sequence 后缀)。

我们的现状：key 暂猜 casanovo / casanovo_sequence，并加了子串兜底。等工具接上跑一次 get_run().tool_name 校准。

PhD 结论：
B3 mzTab 的 index=N 是否就是输入 mgf 的 0-based 顺序？ 需确认

影响：这是谱图 ⨝ 预测的 join 钥匙。两边 index 基准/顺序若不一致 → 张冠李戴。

我们的现状：按「mgf 第 i 张谱 ↔ mzTab index=i」实现(Casanovo 通常如此)。

PhD 结论：
B4 一个 run 是否可能有多个输入谱图 / 输出结果文件？ 需确认

影响：loader 现在按 data_type 选第一个匹配文件。若一次 run 多文件，要改成遍历配对。

我们的现状：按「单谱图 + 单 mztab」处理。

PhD 结论：
B5 保留时间 RT 是否需要进图？ 需确认

影响：RT 是重要的对齐/校验特征。要的话需扩展 mgf 解析器读 RTINSECONDS(现在不读，Spectrum.retention_time=None)。

PhD 结论：
B6 de novo 无 FDR，要不要按 score 阈值过滤低质量预测？阈值多少？ 需确认

影响：数据库搜索用 q_value≤0.01 卡 FDR；Casanovo 没有 FDR/decoy，只有逐肽 score。是否设阈值、设多少由 PhD 定。

我们的现状：全量入图，q_value=None、is_decoy=false，不过滤。

PhD 结论：

C. 建模决策（已采用默认，确认/可调）

C1 Peptide 身份用 peptidoform(带修饰)，裸序列作属性？ 确认默认

默认：节点 key = peptidoform(如 MEEVEES[+79.966]PEK)，stripped_sequence 作属性。理由：定量/修饰分析在 peptidoform 级。

PhD 结论：
C2 谱图峰(m/z+强度)不入图、只留文件指针？ 确认默认

默认：不入图(几十万谱×上百峰会爆)，Spectrum.data_object_id 指回文件，按需回取。

PhD 结论：
C3 图库用 Neo4j + GDS，与 SQLite 并存？ 确认默认

默认：结果/溯源在 SQLite，图结构+图算法在 Neo4j，靠 id 互指；两库无跨库事务，靠 MERGE 幂等。

PhD 结论：
C4 sample_id / condition 怎么定义、从哪来？ 需确认

影响：Sample 节点的身份与分组(差异分析按 condition)。

我们的现状：sample_id 暂从谱图文件名推(sample:<stem>)，condition="" 空。需要真实的样本元数据来源(样本表 / 命名约定 / 上传时带)。

PhD 结论：

D. 图的边界 & 报告

D1 一张图的边界：单实验一张图 / 多实验累积同一张？ 先锁

影响：决定节点 id 的唯一性范围、跨实验比较怎么做、图会长多大。

我们的现状：节点 id 用「文件 oid + index」全局唯一，天然支持累积；但是否真要混多实验由 PhD 定。

PhD 结论：
D2 报告受众：QC 技术报告 / 生物学解读？ 先锁

影响：决定要不要做「生物学解释与注释 Agent」(L2 解释层)。纯 QC 只需指标查询；生物学解读才需要挂注释/通路/RAG。

PhD 结论：

E. 部署 & 下游增强

E1 Neo4j 实例是否装 GDS 插件？连接信息？ 先锁

影响：蛋白推断(gds.wcc 连通分量)依赖 GDS 插件，光装 neo4j 驱动跑会报「未知过程」。另需确认 uri / 账号 / 是否社区版(分库受限)。

我们的现状：默认 bolt://127.0.0.1:7687，GDS 未确认已装。

PhD 结论：
E2 生物学解释要接哪些在线库？ 需确认

影响：决定 MCP_IO 增强通路接哪些：UniProt(蛋白注释) / KEGG(通路) / DeepXiv(文献) / 其它。

PhD 结论：
E3 RAG 本地知识库有哪些语料？ 需确认

影响：实验 SOP / 项目文档 / 数据库说明 —— 有没有现成可对接的文档集，决定 RAG 能不能开、喂什么。

PhD 结论：
过完这张表后：A 组 + B1/B2 + E1 一锁，loader/materializer 就能从「能跑」推到「对接真实数据跑通」；D2 决定要不要展开下游解释层。建议按 A → B → E → C/D 的顺序谈。
