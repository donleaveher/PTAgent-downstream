1. 概览与核心理念

目标:把"原始质谱数据 → 生物学结论"的分析与报告,建在一张关系图谱上。这张图完全从本次实验的输出长出来——节点和边都是实验内部的实体与关系,不去对接 GO/KEGG/UniProt 做外部语义推理。

核心理念:关系即数据,图结构本身就是分析。
蛋白推断、覆盖度、样本质控这些报告指标,不是外挂逻辑,而是图操作的自然结果:蛋白组 = 连通分量,unique/razor = 边的度数,覆盖度 = 支撑肽段的区间并集。把数据建成正确的图,分析就退化成查询。

这也决定了报告生成策略:数值与图结构由参数化图查询稳稳产出,LLM 只在最后做语言润色与异常解读,从根上压住幻觉。

2. 关系图谱 vs 知识图谱 —— 不是二选一,是三层

常见的"关系还是知识"其实是个伪命题。成熟形态是分层的:关系图谱(L0)是地基、无条件要建;知识图谱(L2)只是可选的注释叠加层,且大概率不用自建——把蛋白列表喂给成熟工具(g:Profiler / clusterProfiler / STRING),把结果折回来当节点属性即可。

3. 三层数据架构 —— 图谱接在哪

项目已有两层(都不是科学内容本身):数据平面(SQLite)记文件/运行血缘,编排模型(Pydantic)记流程状态。关系图谱是第三层,职责是把"黑盒文件"解包成可查询的科学实体,并用溯源指针回指数据平面。

设计原则:图谱不复制、不替代数据平面;它展开文件内容成实体,易变的物理路径锁在数据平面,图谱只认稳定的 object_id / run_id。

4. Schema:节点与边

主干 Sample → Spectrum → PSM → Peptide 对两种范式都安全;蛋白层 Protein / ProteinGroup / Quantification 只在数据库搜索范式下挂载。de novo(Casanovo)到 Peptide 即止。

6. 数据流:Materializer(解包入图)

关系图谱通过一个 materializer 接进现有 agent 流——它作为 execute_dag 之后的自动步骤,把工具产出的结果文件解包成图节点。

  1. 给一个 run_id → 查 dp_run,拿到输入谱图文件(input_object_ids)+ 输出结果文件(output_object_ids);
  2. 谱图文件给 Spectrum 属性(m/z、电荷),结果文件给 PSM/Peptide;按 scan 号 join 拼成扁平行 rows;
  3. 分批 UNWIND $rows + MERGE 幂等写进 Neo4j,每个节点带溯源指针;
  4. 成功后在结果文件的 meta_json 标 materialized:true(防重复)。
幂等而非两库事务:SQLite 与 Neo4j 无跨库事务。靠 MERGE 在稳定键上去重 —— 先写 Neo4j、后标 SQLite,中途崩了重跑也安全。

7. 蛋白推断 = 图算法(无手写逻辑)

"肽段—蛋白"是带歧义的二部图:共享肽段把多个蛋白连在一起。蛋白组就是它的连通分量,unique/razor 看肽段的度数。

  • 蛋白组 = gds.wcc 弱连通分量 → 按 componentId 聚成 ProteinGroup;
  • unique = 肽段 BELONGS_TO 度数为 1;
  • razor = 共享肽段按 parsimony 归给证据最多者 (简化版,严格对齐 MaxQuant 需贪心 set-cover)。

8. Cypher 速览

约束(身份 = MERGE 去重键)

CREATE CONSTRAINT spectrum_id IF NOT EXISTS FOR (x:Spectrum) REQUIRE x.spectrum_id IS UNIQUE;
CREATE CONSTRAINT psm_id      IF NOT EXISTS FOR (p:PSM)      REQUIRE p.psm_id      IS UNIQUE;
CREATE CONSTRAINT peptidoform IF NOT EXISTS FOR (e:Peptide)  REQUIRE e.peptidoform IS UNIQUE;
CREATE CONSTRAINT protein_acc IF NOT EXISTS FOR (pr:Protein) REQUIRE pr.accession  IS UNIQUE;

蛋白推断(GDS 连通分量)

CALL gds.graph.project('pep_prot', ['Peptide','Protein'],
     { BELONGS_TO: { orientation: 'UNDIRECTED' } });
CALL gds.wcc.write('pep_prot', { writeProperty: 'componentId' });
CALL gds.graph.drop('pep_prot', false);

MATCH (prot:Protein)
WITH prot.componentId AS gid, collect(prot) AS members
MERGE (g:ProteinGroup {group_id: 'grp_' + toString(gid)})
WITH g, members UNWIND members AS prot
MERGE (prot)-[:IN_GROUP]->(g);

报告查询示例 —— 指标即查询

// 每条肽段被几张谱支持(1% FDR、去 decoy)
MATCH (pep:Peptide)<-[:IDENTIFIES]-(psm:PSM)
WHERE psm.is_decoy = false AND (psm.q_value IS NULL OR psm.q_value <= 0.01)
RETURN pep.peptidoform, count(psm) AS spectral_support
ORDER BY spectral_support DESC;
